    User-Based Thinking

    Learning Overview

    During this week, we covered users and how best to understand them as we develop a project. We first covered and created user personas to get an idea for who would be using the site, then created user stories and user scenarios for those personas.

    User Personas

    User Personas are descriptions of a possible or ideal user of a product or service. They are used to give developers a better idea of what kind of users will use their service, as well as what they would be looking for in terms of features.

    This is a sample user persona I created, with a fleshed out identity to give me an idea of who would want to use the City of Vancouver site. I chose to focus on a more working class, every day kind of persona that would realistically want to use the site. I drew on experience I have with real people. Having volunteered at recreational events before, I knew this was a kind of person who was realistic and common to the Vancouver area.

    Name: Maya Lee
    Age: 35​
    Occupation: Nurse, moved to Vancouver within the past few years.
    Needs:
    -​ A site with up to date and clear information.
    -​ Easy access to other services where applicable.
    Goals:
    -​ Finding and signing up for recreational activities for her and her kids
    -​ Double checking details on public events
    Pain Points:
    -​ Some information on the website is outdated or for things that have happened in the past.
    -​ Information is organized in a way that many sub-topics take you back to other pages.
    -​ Overwhelmed by other unrelated information that appears under similar headings/topics.

    User Stories

    User Stories are an extension of User Personas. They help narrow down the feature list to what hypothetical users would really want, and what kind of problems they would run into. Below are some sample user stories I wrote, using the same persona from above.

    Drawing on the persona I created, I knew that recreational activities and current events were both topics of importance for this specific persona. After looking at the website, the pages for these topics had lots of sub-pages and information to work with, so I chose to focus on them for my User Stories, and later on, what problems I wanted to focus on.

    Persona 2 - Working Mom
    1)​ As a mother, I want to find events and activities near me so that I can plan in advance and take my kids.
    2)​ As a nurse, I want to get reliable current events directly from the city so that I know the information I’m getting is reliable.
    3)​ As a mother, I want to be kept aware of how recreational services are being handled so I can stay up to date with my registrations.

    User Scenarios

    User Scenarios are the final piece in learning how hypothetical users would interact with your service. They are similar to User Stories, directly building off of them but with a more technical viewpoint. The scenarios guide developers through how a user flow would look for a story. Below are user scenarios I created, following the same user persona and using the user stories shown previously. I chose the two user stories I felt were most realistic.

    User Story #1: As a mother, I want to find events and activities near me so that I can plan in advance and take my kids

    Start at home page -> Click the activities/events link in the menu -> Browse current events -> Go to the page of one that looks interesting -> Click on the registration link

    User Story #3: As a mother, I want to be kept aware of how recreational services are being handled so I can stay up to date with my registrations.

    Start at home page -> Click the community/culture link in the menu -> View current news happenings -> Click an article that looks interesting
